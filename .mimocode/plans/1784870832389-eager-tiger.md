# Coze Studio 前端集成计划

## 目标

将 Coze Studio 前端的核心能力（Bot 管理、知识库、Workflow、插件、市场、认证、Playground）集成到当前 `web/` 前端中，合并为统一的新前端。

## 背景分析

### 当前 web/ 前端（保留为主）
- **技术栈**: Vite 5 + React 18 + TypeScript + Tailwind 3.4 + Zustand 5 + React Query
- **独有能力**: Agent YAML 编辑器、AgentLoop 多轮对话、A2UI 流式对话、可观测性面板（6 tab）、MCP 管理、Evolution 基因库、Monitor 面板
- **路由**: 12 个页面，已对接 `/api/v1/*` Superagent API

### Coze Studio 前端（需提取能力）
- **技术栈**: Rush.js + Rsbuild + React 18 + Semi Design + @coze-arch/* (~170 内部包)
- **独有能力**: Bot 创建/编辑/发布流程、知识库管理（文档上传/切片/审查）、Workflow 可视化编辑器（FlowGram）、插件管理（API 调试/Mock）、市场/模板库、用户认证系统、对话 Playground
- **后端 API**: 已被当前后端继承，路由前缀 `/api/*`（非 `/api/v1/*`）

### 关键约束
1. Coze Studio 前端使用 Rush.js monorepo（~170 包），与当前 Vite 单包架构完全不同
2. Coze Studio 的 @coze-arch/* 包深度耦合（bot-api、bot-hooks、bot-semi 等），不能直接引用
3. 后端已继承 Coze Studio 的完整 API handler（32 个文件），路由可用
4. 两个前端的 API 命名空间不同：`/api/v1/*`（Superagent）vs `/api/*`（Coze Studio）

## 集成策略：**渐进式功能移植**

**不直接引入 Rush monorepo**，而是在当前 Vite + Tailwind 架构下，参考 Coze Studio 的页面设计和 API 调用，逐个功能模块重新实现。

理由：
- Rush monorepo 引入成本极高（170+ 包依赖链、Rsbuild 与 Vite 冲突、Semi Design 与 Tailwind 冲突）
- Coze Studio 的 @coze-arch/* 包引用了字节内部服务（Slardar 监控、Tea 埋点），需要剥离
- 当前 web/ 的技术栈更现代、更轻量，已有成熟的组件基础

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Coze Studio API 在当前后端不完整 | 部分功能无法工作 | 先验证 API 可用性，不可用的标记为 TODO |
| 知识库功能依赖 ES/MinIO | 需要完整中间件 | 使用 `make debug` 启动完整栈 |
| Workflow 新节点序列化复杂 | Phase 4 工作量增大 | 优先支持最常用的 3-4 种节点 |
| Coze Studio API 返回格式与前端预期不匹配 | 需要适配层 | 在 coze-api.ts 中做数据转换 |
